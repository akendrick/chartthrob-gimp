# ChartThrob → GIMP Port: Project Outline & Implementation Plan

Source reference: https://github.com/joker-b/ChartThrob (`ChartThrob.jsx`, v1.15, 2019).
Target: a GIMP plugin providing equivalent chart-generation and scan-analysis workflows.

---

## 1. Project Outline

### 1.1 Goals

- **G1 — Functional parity.** Reproduce both ChartThrob workflows: (a) generate a printable
  grayscale calibration chart, (b) analyze a scanned print of that chart and produce a
  tone-correction curve.
- **G2 — Algorithmic fidelity.** Port the core math (paper-tone normalization, dynamic-range
  detection, monotonic curve-point interpolation) exactly, so outputs are numerically
  verifiable against the original algorithm, not just "similar-looking."
- **G3 — Native GIMP implementation.** Use GIMP's real public API (direct gradient fill,
  direct histogram/pixel reads, native curves) instead of replicating Photoshop's
  `ActionDescriptor`/`executeAction` workarounds, which exist only because PS's scripting DOM
  lacks public calls for those operations.
- **G4 — Cross-platform.** One code path for Windows/Mac/Linux (GIMP's PDB is uniform across
  platforms; the original's install instructions had OS-specific folder notes that we don't need).
- **G5 — Testability.** Every piece of core logic must be unit-testable without a running GIMP
  instance, plus have a headless integration-test path runnable in GIMP's batch mode.
- **G6 — No legacy cruft.** Drop the Google Analytics Measurement Protocol v1 telemetry
  (`GaEmitter` in `ChartThrob.jsx`, and the dead duplicate `ps2ga.jsx`) entirely — it's a
  sunset protocol and shouldn't be reintroduced silently in a rewrite anyway.
- **G7 — Third-party-AI reviewable.** Clear module boundaries, type-annotated signatures, and
  docstrings on non-obvious invariants, so another AI (or human) reviewer can audit the port
  function-by-function against the original without re-deriving the math from scratch.

### 1.2 Non-Goals

- Pixel-identical recreation of Photoshop's ScriptUI dialog layout — use GIMP-idiomatic dialogs.
- Support for GIMP versions without GEGL (i.e., pre-2.10).
- Any phone-home telemetry.
- New features beyond ChartThrob 1.15's scope (extra chart sizes, non-grayscale processes,
  etc.) — that's a v2 discussion, out of scope here.

### 1.3 Success Criteria

| # | Criterion |
|---|---|
| SC1 | Given a chart generated by the tool, plus a synthetically-distorted "scan" of it (a known, deliberately non-linear transfer function applied in test code), the recovered correction curve — when composed with the known distortion — is monotonic and flattens tonal response within an agreed tolerance (≤ 2/255 at each of the 14 control points). This is the automated proof that "the math still works." |
| SC2 | Generated chart geometry (patch positions/sizes, strip counts) matches the original's layout formulas 1:1 at a given DPI, verified by comparing computed coordinates (not rendered pixels). |
| SC3 | Every edge case the original explicitly guards against (blank/inverted scan, non-RGB mode, too-small crop, degenerate dynamic range) produces an equivalent user-facing error/warning, never a crash. |
| SC4 | 100% of ported pure-logic functions have unit tests with ≥90% branch coverage. |
| SC5 | The plugin installs and runs end-to-end in a real GIMP session for both workflows, no manual patching. |

### 1.4 High-Level Phases

0. Environment & scaffolding
1. Port pure math/logic layer (GIMP-independent)
2. Port chart-generation workflow
3. Port scan-analysis workflow
4. UI layer & plugin registration
5. Test suites (unit, property, golden, integration/headless)
6. Packaging, docs, third-party-AI review pass

## 2. Implementation Plan

### 2.0 Target Environment (assumption — flag if this should change)

Primary target: **GIMP 3.0.x**, Python 3, via GObject-Introspection (`gi.repository.Gimp`),
registered as a `Gimp.PlugIn` subclass. GIMP 2.10's Python-Fu (Python 2) is legacy; if broader
2.10 compatibility is required later, the pure-logic layer (Phase 1) is Python-version-agnostic
and only Phases 2–4 (GIMP calls, plugin registration) would need a parallel 2.10 code path.

### 2.1 Repository Layout

```
chartthrob-gimp/
  chartthrob/
    __init__.py
    geometry.py         # pure math: layout constants, patch centers, bounds
    curve_math.py        # pure math: normalization, dynamic range, interpolation, verify/negate
    chart_builder.py      # GIMP calls: draws the printable chart
    chart_analyzer.py      # GIMP calls: samples patches, builds the curve
    plugin.py           # Gimp.PlugIn registration, dialogs, main entry points
  tests/
    unit/
      test_geometry.py
      test_curve_math.py
    property/
      test_curve_invariants.py
    golden/
      fixtures/*.json
      test_golden_vectors.py
    integration/
      headless_harness.py
      test_full_roundtrip.py
  docs/
    PLAN.md               # this file
    API_MAPPING.md         # function-by-function original → port mapping
  scripts/
    run_headless_tests.sh
  pyproject.toml
```

### 2.2 Phase 1 — Pure Math/Logic Layer (no GIMP dependency)

Port function-by-function, preserving exact algorithm and edge-case behavior.

| Original (`ChartThrob.jsx`) | Ported to | Notes |
|---|---|---|
| `toGray(C)` | `curve_math.to_gray(rgb) -> float` | Keep the simple average (not the commented-out luminance-weighted variant) — this is a *deliberate* preserved behavior, document it as such rather than "fixing" it. |
| `grayValues(ColorSamples)` | `curve_math.normalize_paper_tone(samples) -> list[float]` | Divide by paper color (sample 0), clamp each channel to 255, surface the "unusually dark — possibly scanned a negative" warning as a return flag rather than an `alert()`. |
| `determineDynamicRange(GraySamples)` | `curve_math.compute_dynamic_range(values) -> DynamicRange` (dataclass: `normalized, min, max, min_idx, max_idx, degenerate: bool`) | Preserve the `dR < 1` degenerate fallback to a linear ramp. |
| `findValueThatGives(origValue, normalizedSamples)` | `curve_math.find_value_for(orig_value, normalized_samples) -> float \| None` | Preserve the inverse-interpolation algorithm exactly, including the `origValue == 0` special case and both "sample values start above/never reach" boundary conditions — return `None` instead of `alert()`-and-`-1`. |
| `verifyCurve(curvePoints)` | `curve_math.verify_curve(points) -> bool` | Return bool instead of alert+return code. |
| negate logic inside `verifyCurve` | `curve_math.negate_curve(points) -> list[point]` | Split out as its own function (`255 - v` per point) so it's independently testable. |
| `patchCenter`, `selectPatch` math, `boundArray`, `gX21`/`gXGrad`/`gXBar`, `resetDpi` | `geometry.ChartLayout` dataclass, built from a DPI value; `geometry.patch_center(layout, i, j)`, `geometry.patch_bounds(layout, i, j)` | Replace the globals (`gWidth`, `gPatch`, etc.) with an explicit, constructed, immutable layout object. |

**Exit criteria:** all functions above exist with type hints, docstrings on non-obvious
invariants, and passing unit tests (see 2.6).

### 2.3 Phase 2 — Chart Builder (GIMP calls)

| Original | GIMP equivalent | Notes |
|---|---|---|
| `boundArray` + `selection.select` | `Gimp.Image.select_rectangle(...)` | |
| `grayPatch` | `Gimp.context_set_foreground(...)` + `Gimp.Image.select_rectangle(...)` + `Gimp.Drawable.edit_fill(...)` | |
| `drawGradient` / `verticalGrad` (raw `ActionDescriptor`, ~100 lines) | `Gimp.Drawable.edit_gradient_fill(...)` | Direct public call — eliminates the entire `charIDToTypeID` boilerplate block from the original. Call this out explicitly in `API_MAPPING.md` as a simplification, not a behavior change. |
| `drawBars`, `horizLine`, `gradLine` | Composed from the same select+fill/gradient primitives | |
| `writeText` | `Gimp.text_fontname(...)` | |
| `outStroke` | `Gimp.Image.select_rectangle(...)` + `Gimp.Drawable.edit_stroke_selection(...)` | |
| `make101`, `make21`, `buildChart` | `chart_builder.build_chart(image, layout, options)` | Composes the above using `geometry.ChartLayout` from Phase 1 — layout math itself must not be reimplemented here, only called. |

**Exit criteria:** `build_chart()` produces an image matching SC2 (layout coordinates match
the original's formulas at a reference DPI, verified by unit test against `geometry.py`, not
by visual inspection).

### 2.4 Phase 3 — Scan Analyzer (GIMP calls)

| Original | GIMP equivalent | Notes |
|---|---|---|
| `duplicateDocument` | `image.duplicate()` | |
| mode-check + `changeMode(ChangeMode.RGB)` | `Gimp.Image.convert_rgb()` guarded the same way (bitmap/CMYK/duotone/grayscale/indexed → convert, with the same user-facing failure message on exception) | |
| `patch()` (`applyAverage()` + `getColorAt` histogram-bin-scan hack) | `Gimp.Drawable.histogram(channel, selection_bounds)` → mean directly | **Flagged simplification:** PS's `applyAverage()` (blur flat) + pixel-read-via-histogram-bin-scan is a workaround for lacking a direct "read pixel" call; GIMP's histogram mean over the selection is a direct, more robust equivalent. Must be covered by a golden-vector test proving numeric equivalence within tolerance, not assumed. |
| `curveLayer` (raw `ActionDescriptor`, "Crvs" adjustment layer) | **Open technical spike** — GIMP has no direct Photoshop-style non-destructive "Curves adjustment layer" concept exposed identically via the PDB. Candidates to evaluate: (a) apply `Gimp.Drawable.curves_spline(...)` destructively to a duplicated/new layer that stands in for the "Print Curve" layer; (b) export the computed curve as a GIMP Curves tool preset file so users can load it onto other images the way the original let users drag a curves layer between documents. **Decide during Phase 3, document the choice and rationale in `API_MAPPING.md` before writing tests against it.** | |
| `scanResultsReport` | `plugin.py` dialog, reusing wording from `verify_curve`/dynamic-range results | |
| `scanChart` | `chart_analyzer.analyze_chart(image, layout, options) -> CurveResult` | Orchestrates the above; must preserve the original's guard: fewer than 2 valid curve points → abort with the "not enough samples" equivalent. |

**Exit criteria:** headless round-trip test (2.6) passes SC1.

### 2.5 Phase 4 — UI / Plugin Registration

- Register as a `Gimp.PlugIn` subclass exposing procedures mirroring `userDialog()`'s choice
  between "analyze open scan" and "build new chart."
- Use `Gimp.ProcedureConfig` / `Gimp.ProcedureDialog` to auto-generate the parameter dialog
  (chart name, label, DPI, Numbers/Outlines toggles, Outline-Sample-Areas, Negate-Output-Curve,
  Excessive-Messages) — this replaces the hand-built ScriptUI widget tree with declarative
  parameter specs.
- Port `helpDialog()` content (the step list) near-verbatim from the README into a help
  dialog or procedure description.
- No telemetry call anywhere in this layer (G6).

**Exit criteria:** SC5 — installs and runs both workflows end-to-end in a real GIMP session.

### 2.6 Phase 5 — Test Suites

This is the section most relevant to third-party AI review — be exhaustive and explicit about
*what is being asserted and why* in every test file's module docstring.

**Unit tests (pytest, no GIMP required) — `tests/unit/`**
Full coverage of `curve_math.py` and `geometry.py`:
- `normalize_paper_tone`: normal case; dark-paper warning-flag case; per-channel clamp above 255.
- `compute_dynamic_range`: normal spread; degenerate all-equal input (must hit the linear-ramp
  fallback, not divide by zero); correct min/max index tracking.
- `find_value_for`: exact match; interpolation between neighbors; `orig_value == 0` boundary;
  boundary at the highest sample; duplicate-value (`delta == 0`) case; unreachable-value
  returns `None` rather than raising.
- `verify_curve` / `negate_curve`: monotonic input passes; non-monotonic input flagged;
  `negate_curve(negate_curve(x)) == x` identity.
- `geometry`: `patch_center` correctness at grid corners/center; DPI scaling preserves ratios
  at 72/150/300/600/1200 dpi; `boundArray`-equivalent ordering.

**Property-based tests (hypothesis) — `tests/property/`**
- For randomly generated monotonic sample arrays, `compute_dynamic_range` output stays within
  `[0, 255]`.
- `find_value_for` output is monotonic non-increasing as `orig_value` increases (state this
  inverted-mapping invariant explicitly in the test docstring).
- `verify_curve` never raises on any synthetically-generated monotonic curve.
- `negate_curve` is an involution (self-inverse) for all generated point sets.

**Golden vector tests — `tests/golden/`**
Fixed input arrays with pre-computed expected outputs, stored as JSON fixtures, asserted with a
float tolerance — this is what lets a reviewing AI confirm the port didn't silently change
behavior versus "looks similar":
- A clean, ideal near-linear scan.
- A low-contrast (compressed dynamic range) scan.
- A dark-paper-tone scan.
- A scan with one clipped/dead patch.
- The `patch()` histogram-mean vs. original blur+bin-scan equivalence check (from 2.4).

**Stress tests (adversarial/edge-case inputs)** — each with an explicit expected behavior,
implemented as parametrized pytest cases:

| # | Input | Expected behavior |
|---|---|---|
| 1 | All 101 patches identical value | Degenerate dynamic range → linear-ramp fallback, no crash |
| 2 | Inverted scan (paper tone below threshold) | "possibly scanned a negative" warning flag returned |
| 3 | Extremely small crop (sample area smaller than patch grid) | Clear error, or documented degraded-but-monotonic output — not silent garbage |
| 4 | DPI below 72 | Clamped to 72, matching original |
| 5 | DPI absurdly high (e.g. 4800) | Layout math doesn't overflow; rounds sanely |
| 6 | Non-RGB image fed to analyzer (grayscale/CMYK/indexed/bitmap) | Attempts conversion; on failure, clean error, no partial state left behind |
| 7 | Negate toggle + degenerate/linear-fallback curve | Still valid, monotonic-after-negation output |
| 8 | `orig_value` exactly 0 and exactly 255 | Correct boundary handling, no off-by-one |
| 9 | Fewer than 2 valid curve points | Aborts with "not enough samples," matching original's `i < 2` guard |
| 10 | Non-progressive (non-monotonic) curve points, e.g. from a mis-cropped chart | Caught by `verify_curve`, never written into an output curve |
| 11 | Full round-trip: build → apply known monotonic distortion → analyze | Recovered curve approximately cancels the distortion within tolerance — this is SC1, made into an automated test rather than a one-off manual check |

**Integration / headless GIMP tests — `tests/integration/`**
- `scripts/run_headless_tests.sh` drives GIMP's batch interpreter to: load the plugin, invoke
  build-chart, save output; apply a synthetic distortion via a small script; feed it back into
  analyze-chart; extract curve points via a debug-dump hook; compare against tolerance.
- Must be scriptable/CI-runnable without a GUI.
- `headless_harness.py` must carry a module docstring explaining the round-trip proof in plain
  terms, so a reviewing AI doesn't have to reverse-engineer intent from the code alone.

**Code-review readiness checklist**
- Full type hints on every pure-logic module (`from __future__ import annotations`; dataclasses
  for structured returns instead of bare tuples where it aids clarity).
- Docstrings only where an invariant isn't obvious from the name/signature (e.g., why
  `find_value_for` uses inverse interpolation, why negation is `255 - v`, why normalization
  divides rather than subtracts) — no restating-the-obvious comments.
- `docs/API_MAPPING.md`: every original `ChartThrob.jsx` function mapped 1:1 to its Python
  equivalent and the GIMP calls it uses, with any intentional behavior deviation explicitly
  flagged (never silent).

### 2.7 Phase 6 — Packaging & Docs

- README: install steps (GIMP 3 plugin folder + executable-file naming convention).
- `docs/API_MAPPING.md` finalized and cross-checked against `ChartThrob.jsx` line-by-line.

- Tag `v0.1.0` once all Phase 5 acceptance criteria are green.
